没有 React、没有 Canvas：拆解 Designed to Scale 的纯原生 SVG 等轴测引擎与 40 课系统设计图谱

2026-11-18 18 min read # 交互式学习 # SVG # 前端架构 # 系统设计 # 数据可视化

传统的系统设计课程往往困在两种极端里：要么是长达几十页的纯文字八股加上几张静态流程图，要么是在网页里硬塞一个臃肿的 WebGL 画布。最近我用无头浏览器打开了资深创意编码工程师 Dilum Sanjaya 刚上线的互动式系统设计课程 Designed to Scale，在把玩了几节等轴测动画课之后，顺手抓下了它的生产环境构建产物与页面 DOM 做了一次彻底的逆向审计。

结果出乎我的意料：这套涵盖 9 大模块、40 门课程、共计 445 个分步动态演练的交互平台，竟然没有引入 React、Vue、Three.js 或 D3 中的任何一个。整个前端仅靠 784,539 字节的纯原生 ES Module（加上 64,267 字节的 CSS）支撑起 2.5D 等轴测三维渲染、多边形自动避障相机、路径弧长物理发包、21 语种零闪烁切换以及带拼写容错的客户端全文检索。这篇文章我将结合实机浏览与生产包代码拆解，完整还原这座“零框架交互式教学引擎”的底层构造与课程版图。

[!NOTE] 调研基线与审计范围说明
本文所有交互体验与性能数据均基于我在 2026 年 11 月 18 日对 https://designed-to-scale.vercel.app/#/（HTTP 响应头 last-modified: Mon, 16 Nov 2026 16:29:12 GMT）的实机访问，以及对其生产构建产物 index.html（6,347 字节）、主脚本（784,539 字节）与样式表（64,267 字节）的逐模块静态分析。

一、反直觉的技术栈：为什么 40 门互动课不需要框架与 WebGL？

当我检查 index.html 的 <div id="app"></div> 以及主脚本的 DOM 操作统计时，首先被一组数字吸引住了：整个应用仅仅调用了 7 次 document.createElement、1 次 document.createElementNS 与 33 处 innerHTML 模板更新，没有任何 __SECRET_INTERNALS、__vue 或 __svelte 运行时痕迹，构建工具链只用到了 Vite + LightningCSS。

作者 Dilum Sanjaya（@DilumSanjaya）选择用极简的“数据驱动 DSL + 纯原生 SVG DOM”替代主流框架与 3D 引擎，背后隐藏着一套非常清醒的工程账：

  • 教学图元高度同构：系统设计课里的服务器、负载均衡器、数据库圆柱、消息队列、客户端手机与哈希环，本质上只有 10 类有限图元，却要在 445 个步骤之间频繁发生“从 1 台服务器裂变成 3 台并连线”的渐进转场。在纯 SVG 中直接控制 requestAnimationFrame 插值补间，远比在 React Virtual DOM 里协调上百个动画节点来得直接。
  • 矢量印刷级锐度与极低带宽：整套平台采用了“暖纸墨线（Warm Paper）”的编辑室美学（浅色底 #f4ebe0、墨色边框 #1d1b18，暗黑底 #211e1a）。无论用户在 HiDPI 视网膜屏上将画布捏合放大到多少倍，SVG 矢量线条和等宽字体标签永远保持锐利，且主样式表仅 63 KiB。

顺着主脚本的渲染管线向下梳理，我把这套自研图形引擎拆成了五层紧密咬合的架构。

二、图形引擎深潜：仅用 2:1 投影公式造出可交互的三维世界

在没有 Three.js 的情况下，Designed to Scale 是如何在 <svg class="stage-svg"> 里画出极具立体感的斜 45 度等轴测机房拓扑的？我在源码中找到了最核心的几行数学原语。

1. 纯数学 2:1 等轴测投影与画家深度排序

引擎里所有的节点坐标 (x, y, z) 都处于逻辑网格空间中，通过一个极简的投影函数 j(x, y, z) 直接映射到二维 SVG 画布坐标：

const project = (x, y, z = 0) => [
  round(14 * (x + y)),
  round(7 * (x - y) - z)
];

这正是经典的 2:1 等轴测轴测图比率（水平每走 1 格对应 14px，垂直投影高度减半为 7px，高度 z 轴直接向上抬升像素）。紧接着，建筑体的顶面、左侧面与右侧面并不需要人工手算四个顶点，而是通过三条标准的 SVG transform="matrix(...)" 仿射矩阵直接把二维图形贴到三个正交面上：

  • 顶面地板平面：matrix(1 0.5 -1 0.5 rx ry)
  • 右立面：matrix(1 -0.5 0 1 rx ry)
  • 左倾斜面：matrix(1 -0.5 1 0.5 rx ry)

当节点在步骤切换期间发生 x、y 位置漂移（比如“一致哈希”课程中节点滑上哈希环）或 lift 纵向入场弹跳时，动画循环内的 sortDepth() 会实时计算每个三维实体的深度权重 cx - cy（并将地板/网格锁定在 -10000、消息队列锁定在 -1000、角落 HUD 卡片锁定在 10000），通过重新排布 .layer-ents 子节点顺序，用画家算法彻底解决三维前后遮挡穿透问题。

2. 自动取景、四角卡片避障与相机滞回防抖

做过交互式图表的开发者一定踩过这样的坑：如果画面角落固定浮着一块参数说明面板（panel），当画布缩放或步骤增加新节点时，节点很容易钻到卡片底下被挡死。

我审计 planFor() 与 cardClear() 时，发现作者写了一套相当严谨的几何避障求解器：

  1. 多边形与包围盒双检：对于当前步骤的每一个三维实体，引擎都会同时记录它的屏幕外接矩形（boxes）与精确等轴测轮廓多边形（polys）。
  2. 四角穷举与步进缩退：在分配视口 viewBox 时，算法以 0.05 为步长递减测试缩放倍率，并在每个倍率下依次尝试右上（tr）、右下（br）、左上（tl）、左下（bl）四个停靠角，利用射线法点在多边形内判定（If）与线段相交测试（Rf），确保悬浮说明卡与任何实体都不发生哪怕 1 像素的重叠。
  3. 跨步骤相机滞回（Hysteresis）：相邻两个教学步骤之间，如果新场景的所有实体依然落在上一帧相机视野内边距 12px 以内、且中心偏移比例小于 0.12（或 0.18），引擎就会刻意复用上一帧的 viewBox。这一招非常高明——它消除了用户连续按 → 切步骤时画面无意义的轻微跳动，只有当拓扑确实大幅扩张时，镜头才会用三次方缓动平滑拉开。

3. 30 轮二分边界裁剪与路径弧长物理发包

连线与动画粒子同样体现了这套引擎的精雕细琢：

  • 连线精准贴合立体边缘：普通 SVG 连线往往从节点 A 的中心连到节点 B 的中心，导致箭头扎进方块内部或被挡住。这里的 Tr() 与 Er() 函数会对所有路径的首尾线段执行 30 轮二分搜索，精确找出射线穿出实体凸包多边形的那一个交点，再向外推开 n 像素，让箭头和虚线干干净净地停在三维机箱外框边缘。
  • 沿任意贝塞尔路径飞行的 12 类数据包：在 stepPackets() 的 requestAnimationFrame 主循环（单帧步长 dt 被钳制在 50ms 以内防止切后台回来瞬移）中，引擎并没有手写分段坐标插值，而是直接调用浏览器的 SVGPathElement.getTotalLength() 与 getPointAtLength()。不论连线是直折线还是绕过障碍的圆角曲线，请求包（req）、重负载包（heavy）、响应包（res）、慢查询（slow）、毒丸消息（poison）、心跳包（ping）都能顺滑贴线飞行，甚至支持在服务端节点上亮起白边闪烁（pkt--held 模拟长连接挂起/处理耗时），到达终点时依据链接预设的 fail 概率实时爆出红色叉号粒子（fx--fail）或绿色完成涟漪（fx--ok）。

4. 单套色板通吃暗黑模式 + 离屏 Canvas 文本测宽

更令我拍案叫绝的是它处理暗黑模式与多语言排版的方式：

  • 运行时 HSL 自动暗黑反色：全站 40 门课、上百张图元并没有维护第二套暗黑版 SVG 配色。开启暗黑模式后，pf() 会用正则扫过生成的 SVG 片段，跳过显式映射表里的极少数锚点色后，把所有暖纸色与柔和马卡龙粉彩（#f4ebe0、#dfebf9、#e2f2d7 等）实时转换成 HSL 色彩空间并压暗提纯、缓存进 Map。这意味着未来哪怕再新增 40 门课，暗黑主题依然零额外美工成本。
  • CJK 与 RTL 文本的离屏 Canvas 测宽：SVG 原生不支持像 CSS Flexbox 那样让胶囊标签根据文字自动撑宽。针对拉丁字母，引擎用字符数乘以 0.6em 极速估算；一旦检测到中文、日文、韩文、阿拉伯语或希伯来语等非纯拉丁字符，立刻唤醒一个隐形 <canvas> 上下文，读取当前页面实时生效的 --font（默认 JetBrains Mono），用 ctx.measureText(str).width 实测真实像素宽并缓存，同时监听 document.fonts 的 loadingdone 事件自动清缓存重算——这就是为什么切换成简体中文后，图里每一枚“→ 203.0.113.7”或“一致性哈希”药丸标签都严丝合缝、绝不溢出边框的秘密。

三、课程体系全景拆解：9 大模块、40 门课、445 步的演进逻辑

摸清了图形底座，我再把视角拉回到内容本身。Designed to Scale 覆盖了从单机 HTTP 请求到大规模分布式系统的完整知识图谱，全部 40 门课程均已完整上线可交互（合计 445 个独立分步），且每门课都严格遵循统一的教学叙事节拍。

模块序号与主题 课时数 涵盖核心课程清单 教学核心主线
01. 基础（Foundations） 3 课 一个请求的旅程、延迟与吞吐量、估算（Napkin Math） 建立耗时直觉：DNS/TLS 往返、排队论与量级估算
02. 扩展（Scaling） 5 课 垂直还是水平、负载均衡、无状态服务、缓存、内容分发（CDN） 从单机打满到无状态水平扩容与边缘卸载
03. 数据与存储（Data & Storage） 11 课 SQL vs NoSQL、索引、存储引擎、复制、分片、一致性哈希、大规模唯一 ID、CAP 与一致性、共识与 Leader、事务与隔离、文件与媒体 全站最重头戏：B+Tree vs LSM-Tree、Raft 选举、分片热点与环形迁移
04. 通信（Communication） 4 课 REST/RPC/GraphQL、消息队列、发布/订阅与事件、实时更新 同步接口演进、异步削峰填谷、毒丸死信与 WebSocket 推送
05. 可靠性（Reliability） 4 课 冗余与故障转移、限流、超时与重试、可观测性 惊群重试风暴（指数退避+抖动）、令牌桶限流与链路追踪
06. 架构（Architecture） 4 课 单体还是微服务、服务发现、Saga 与分布式事务、批处理与流处理 组织边界权衡、最终一致性补偿事务与 Kappa/Lambda 流批一体
07. 安全（Security） 3 课 认证、授权、加密与密钥 Token/Session 边界、RBAC/ABAC 与密钥轮换
08. 交付（Shipping） 2 课 测试、CI/CD 与部署 测试金字塔、蓝绿/金丝雀发布与零停机回滚
09. 完整系统（Whole Systems） 4 课 HLD 与 LLD、设计短链接服务、设计信息流、设计聊天系统 综合实战：推拉混合信息流（应对 5000 万粉丝名人效应）、WebSocket 网关掉线重连风暴与幂等游标同步

仔细观察这 445 个步骤的标签分布，还能读出作者在内容编排上的克制：

  • 问题驱动（problem: 120 步） 先于方案出现——永远先用高并发故障动画把单机/单库压红（heat: 1、DOWN 标签、红色报错叉号），再引出 技术原理解法（technique: 106 步；solution: 97 步）；
  • 权衡与洞见（insight: 39 步；tradeoff: 20 步；setup: 23 步） 穿插其中，专门揭示“平均值掩盖极端偏斜”（比如信息流课程中普通用户 200 粉丝与顶流明星 5000 万粉丝的扇出写入灾难）或“可用性与一致性的按功能分级取舍”（聊天系统里消息必须持久有序，而“正在输入…”和在线状态则容忍过期）；
  • 固定收尾（recap: 40 步） 每课末尾给出一张对比决策表（.compare）与验收清单，通过率与当前完成进度实时持久化在本地 localStorage（sdt:done、sdt:last）中，无需任何后端账号体系。

四、藏在引擎里的三项硬核基建：820 个语言切片、混合搜索与预埋朗读

除了主舞台的等轴测动画，我在审计主脚本后半段时，还挖出了三个极具参考价值的工程子系统：

1. 21 语种按需切片与 RTL 双向文字隔离

全站支持英语、简繁体中文、日语、韩语、阿拉伯语、希伯来语等共计 21 种语言。如果把 21 份翻译全打包进首屏 JS，体积会瞬间膨胀数倍；作者通过 Vite 的 import.meta.glob('./*/ui.json') 与 import.meta.glob('./*/lessons/*.json')，在构建期将 20 个非英语语种拆分成 820 个独立 ES Module 切片（20 × 41）。用户切换为简体中文时，浏览器只会按需拉取公共 UI 词条和当前正在阅读的这一课的两个小文件，再由递归翻译器 dp() 动态替换课程文案、HUD 指标与 SVG 内部节点标签。

为了防止非英语用户在加载切片前看到一闪而过的英文原文（FOUC），index.html 的 <head> 同步脚本会先于首绘判定语种并挂上 data-lang-pending="1" 隐藏画布、针对阿拉伯语和希伯来语提前设置 dir="rtl"，甚至对混排在 RTL 文本中的英文技术词（如 TCP、WebSocket）自动插入 Unicode 右向标记（U+200F）防止标点错序。

2. 纯前端实现的多字段加权 + 拼写容错检索引擎

按下 Cmd+K（或 Ctrl+K）呼出的搜索面板，背后的实现远超一般的 Array.filter(includes)，几乎是一座浓缩在前端内存里的迷你搜索引擎：

  • 自动抽取概念词典：构建索引时，引擎扫描全站 445 个步骤，把所有 <span class="term">...</span> 标记的技术名词自动聚合成独立的 concept 词条，甚至把三维 SVG 图表里的节点标题、胶囊标签和连线文字全部纳入检索字段，按 term(10) > title(8) > short(6) > body(3) > callout(2) 加权计分。
  • 混合 CJK 二元组与 21 语种停用词：针对拉丁系语言做 NFKD 变音符号折叠、词干提取（-ing/-ed/-ies）与 21 语种停用词过滤；针对中、日、韩连续文字，自动切分成重叠二元组（Bigrams）（如将“一致性哈希”拆为“一致”“致性”“性哈”“哈希”），同时保留混合其中的英文缩写（如 SQL、NoSQL、Raft）。
  • 行业缩写同义词与 Damerau-Levenshtein 纠错：内置 db → database、lb → balancer、2pc → twophase、wal → writeahead、lsm → logstructured 等系统设计缩写词表；当用户输入长于 5 字符且未命中精确词时，还会自动启用允许相邻字符换位（Transposition）的 Damerau-Levenshtein 模糊匹配（容忍编辑距离 ≤2\le 2≤2 的手滑拼错）。

3. 代码已成型、但被特性开关藏起来的“盲盒彩蛋”

在实机测试与源码交叉比对时，我也清晰确认了这款产品的当前边界与未上线规划：

  • 三个顶部导航栏目尚未开放：实机点击顶部栏的 Practice（练习题）、Design Lab（自由设计实验室）与 Cheatsheets（速查表），页面目前均会弹出“coming soon”提示，暂未开放交互。
  • 一套完整的 Web Speech 语音朗读引擎已就绪但处于关闭状态：我在生产包末尾发现了一套非常精致的播音模块——它使用浏览器原生的 Intl.Segmenter 按语种断句、以 220~308 字符切片绕开系统语音引擎的超时截断、优先筛选离线本地语音包（localService），并且编写好了类似卡拉 OK 的逐段高亮样式（.is-reading / .is-paused）和 L / P 快捷键绑定。不过在当前线上版本中，它被一个常量开关 {readAloud: !1} 暂时屏蔽了，大概率会在后续迭代中随着 Practice 一起解锁。

[!TIP] 高效学习与键盘快捷键建议
实机体验这 40 门课时，我最推荐直接用桌面端键盘流配合“全景/全屏”功能：← / → 切分步演进、R 一键重放当前拓扑动画、Space 暂停数据包流观察瞬时状态、Cmd+K 全局检索任意架构术语；遇到像“设计聊天系统”这种多网关大场景，双击画布任意节点即可平滑放大 2 倍并支持拖拽漫游，点右上角 Fit 一键复位全局视角。

五、总结：一次极高完成度的“工程美学”示范

花半天时间把 Designed to Scale 从视觉表现一直拆到字节码级前端实现后，我最大的感受是：好的交互式技术教育工具，不一定非要堆砌最重的全家桶，关键在于针对领域问题量身裁剪抽象层。

Dilum Sanjaya 用不到 800 KB 的原生代码，把系统设计里最难讲清楚的“动态并发与故障传播”变成了可以暂停、缩放、单步回放的等轴测物理沙盘，同时在多语言按需切片与离线检索等细节上保持了极高的工程洁癖。对于正在学习分布式系统设计的工程师而言，这 40 门免费课程本身就是极其优质的可视化教材；而对于前端架构师与独立开发者来说，它更是一份教科书级别的“零框架原生 SVG 引擎”参考样本。
